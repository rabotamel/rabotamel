# Bot Rotator

Telegram-бот на aiogram 3 + FastAPI с админ-панелью и автоматической ротацией токенов.
Токены и профили хранятся в PostgreSQL (Neon). Деплой — Render (один Web Service).

## Структура

```
main.py              # FastAPI + запуск супервизора бота (lifespan)
app/
  config.py          # переменные окружения
  db.py              # движок SQLAlchemy/asyncpg, адаптация URL Neon
  models.py          # таблица bot_profiles
  repo.py            # операции с БД
  manager.py         # запуск бота, мониторинг, горячая ротация токенов
  handlers.py        # логика бота: капча, приветствие
  greeting.py        # рандомизированное приветствие (синонимы, эмодзи, компоновка)
  texts.py           # реестр рандомизируемых сообщений (капча, приветствие, ...)
  sandbox.py         # логика вкладки «Песочница»
  currency.py        # курс 🍬/₽/$ и разбор сумм
  messaging.py       # отправка сообщений бота (с картинкой над текстом)
  auth.py            # вход по паролю (cookie)
  events.py          # шина событий для SSE и баннеров
  stats.py           # пользователи, прошедшие капчу (в памяти + пакетная запись в БД)
  captcha.py         # капча «выбери фрукт»: словарь фруктов, формулировки, конфиг бота
  avatars.py         # аватарки: сайт → Telegram и Telegram → сайт
  push.py            # Web Push
  web.py             # страницы и API панели
  templates/login.html
  static/app.html    # интерфейс панели
  static/sw.js       # service worker для push
render.yaml          # blueprint для Render
NOTES.md             # заметки для разработки: правила рандомизации сообщений бота (ЧИТАТЬ ПЕРЕД ПРАВКАМИ)
tests/               # проверки приветствия и капчи (python -m unittest discover tests)
```

## Деплой

1. **Neon**: создайте проект, скопируйте Connection string (`postgresql://...?sslmode=require`).
2. **GitHub**: залейте содержимое папки в репозиторий.
3. **Render**: New → Blueprint (подхватит `render.yaml`) или New → Web Service вручную:
   - Build: `pip install -r requirements.txt`
   - Start: `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1`
   - Health check path: `/healthz`
4. Переменные окружения (Render → Environment): `DATABASE_URL`, `ADMIN_PASSWORD` (обязательно), `ADMIN_CHAT_ID`, `VAPID_SUBJECT` (по желанию).
   Вместо переменной можно создать Secret File с тем же именем (`DATABASE_URL`) — он читается из `/etc/secrets/DATABASE_URL`.
   Если переменной нет, сервис всё равно поднимется и откроет порт, а страница панели покажет, чего не хватает.
5. Откройте URL сервиса, введите `ADMIN_PASSWORD` на странице входа и добавьте первый токен. Бот запустится сразу.
   Таблицы создаются автоматически при старте.

Локально: `pip install -r requirements.txt`, задайте переменные из `.env.example`, затем `python main.py`.

## Как работает ротация

- Активен всегда один токен (в БД это гарантирует уникальный индекс). Очередь — по возрастанию `id` среди статуса `queued`.
- Токен выводится из ротации (`blocked`, причина пишется в `last_error`), если:
  - Telegram отвечает 401/404 (токен недействителен, отозван, бот удалён);
  - флуд-контроль просит ждать дольше `FLOOD_ROTATE_THRESHOLD` секунд (по умолчанию 300);
  - подряд `NETWORK_FAIL_THRESHOLD` сетевых ошибок (по умолчанию 8);
  - polling упал `MAX_POLLING_CRASHES` раз подряд (по умолчанию 3).
- Дальше супервизор в том же процессе берёт следующий `queued` токен, поднимает нового бота, обновляет имя/описание и
  запускает polling. Перезапуск приложения на Render не нужен.
- В очередь можно добавить бота **без токена** (шаблон «про запас»): в панели он помечен красным «Без токена — это только
  шаблон». Такой бот не запускается и не может стать основным, супервизор его пропускает. Токен добавляется позже
  (шестерёнка → редактировать → поле токена), после чего бот становится обычным запасным. Заменить уже заданный токен нельзя.
- Если очередь пуста (или в ней только боты без токена) — приложение продолжает жить, а панель показывает предупреждение; бот стартует, как только вы добавите токен.
- Из панели можно вручную сделать любой бот активным, вернуть заблокированный в очередь, изменить профиль или удалить бот.

## Профиль

При старте и при каждой смене токена вызываются `getMyName`/`setMyName` и `getMyDescription`/`setMyDescription`
(только если значение отличается и не пустое). У Telegram есть лимит на частоту смены имени — при `retry_after`
бот просто пропустит обновление и повторит при следующем старте.

## Важно знать

- **Аватарка** сохраняется в БД и показывается в панели, но в Telegram не загружается: в aiogram нет готового
  метода для этого. Установить фото можно через @BotFather. Если в актуальном Bot API такой метод появился —
  добавить вызов нужно в `BotManager._apply_profile`.
- **Free-план Render усыпляет сервис** после ~15 минут без входящих запросов, и бот перестаёт опрашивать Telegram.
  Либо платный план, либо внешний пинг `/healthz` каждые 5–10 минут (например, UptimeRobot).
- **Один экземпляр.** Не включайте несколько инстансов/воркеров: два процесса с одним токеном дадут конфликт `getUpdates`.
  При деплое Render ненадолго запускает старую и новую версию параллельно — короткие ошибки 409 в логах нормальны.
- **Токены лежат в БД открытым текстом** (боту они нужны в исходном виде). Панель защищена Basic-авторизацией и
  показывает токены только в маскированном виде; открывайте её только по HTTPS (Render это делает сам).
- Миграции не используются: таблица создаётся через `create_all`. При изменении схемы подключите Alembic.

## Панель

- **Вход** — один пароль (`ADMIN_PASSWORD`), форма на самой странице; после 5 неверных попыток IP блокируется на минуту. Смена пароля разлогинивает всех.
- **Вкладка «Бот»** — текущий основной бот, токен (маскированный, можно показать), число пользователей в реальном времени и время работы в роли основного.
- **Вкладка «Токены»** — очередь: зелёная обводка и «1» у основного, синие 2, 3… у запасных. «Редактировать» включает режим с перетаскиванием (три полоски) и корзиной с подтверждением; тап по карточке в этом режиме открывает правку профиля.
- **Счётчик пользователей** — Bot API не отдаёт список пользователей, поэтому считаются только те, кто прошёл капчу у этого бота. Число хранится в памяти, в БД сбрасывается пачкой (сразу после прохождения капчи и раз в 15 с), в браузеры уходит через SSE.
- **Вкладка «Песочница»** — действует на основного бота: выдача/изъятие 🍬 по @username или ID (знак +/− слева, валюта 🍬/₽/$ справа от суммы, курс 1🍬 = 0,8 ₽ = 0,01 $; при выдаче в 🍬 пользователю приходит «Вы получили +N🍬», в ₽/$ — «Вы купили N🍬 за …», при изъятии — ничего), удаление пользователя из базы и «Уникальные текста» (кнопка «Перенаписать текста» заново подбирает все тексты бота). Каждое действие переспрашивается.
- **Сбои и баны** — жёлтый баннер сверху у всех открытых панелей + Web Push. Если токен недействителен: при наличии запасного — переключение на него, токен помечается заблокированным; запасных нет — токен удаляется. Временные сбои (сеть, флуд) при наличии запасного тоже ведут к замене, а без запасного токен остаётся и попытки продолжаются.
- **Push** — кнопка с колокольчиком вверху; работает после разрешения уведомлений в браузере. Ключи VAPID создаются автоматически и хранятся в БД. На iPhone push работает только если сайт добавлен на экран «Домой».

## Капча

- Новый пользователь (его нет в таблице `bot_users`) при `/start` и при любом первом сообщении получает капчу: задание с названием фрукта **жирным** и 4 кнопки с эмодзи.
- Неверный ответ: сообщение удаляется, сразу приходит новое — те же 4 фрукта и то же задание, но кнопки в другом порядке (он всегда отличается от предыдущего).
- Верный ответ: сообщение удаляется, пользователь записывается в БД (сразу, не дожидаясь периодического сброса), приходит приветствие. Больше капча ему не показывается.
- Конфигурация капчи (формулировка, 4 фрукта, правильный фрукт) создаётся для каждого бота один раз при первом запуске, хранится в `bot_profiles.captcha_config` и не меняется, пока жив этот бот (кроме функции «Уникальные текста» в «Песочнице»). Для нового бота генерируется новая; набор фруктов подбирается так, чтобы не совпадать с уже занятыми другими ботами.
- Правильный фрукт входит в конфигурацию бота (не перевыбирается между попытками). Благодаря этому проверка не хранит состояние по пользователям и переживает перезапуск сервиса.
- Фрукты, эмодзи и формулировки — в `app/captcha.py` (`FRUITS`, `LEADS`, `ACTIONS`), их можно расширять.
- Пользователи, которые уже были в `bot_users` до этой версии, считаются прошедшими проверку.

## Конфеты 🍬

В `bot_users.candies` у каждого прошедшего капчу пользователя свой счётчик (стартует с 0), он показывается в приветствии. Менять баланс можно из «Песочницы» или функциями `repo.get_candies(bot_id, user_id)` и `repo.add_candies(bot_id, user_id, delta)`.

## Приветствие

- После капчи (и на каждый `/start` у прошедшего капчу) бот шлёт приветствие: заголовок с названием бота, два пункта про анонимность и отсутствие следов, строка баланса. Баланс подставляется из БД, `🍬` в строке баланса не меняется никогда.
- Для каждого бота при первом запуске подбирается свой вариант: синонимы, согласованные по стилю эмодзи и одна из 4 компоновок (классическая, пункты местами, маркеры/жирные ключевые слова, цитата у пунктов/«воздух»; баланс в цитату не оформляется). Готовый шаблон хранится в `bot_profiles.texts_config` и не меняется, пока жив бот. Словари и компоновки — в `app/greeting.py`.
- Общая схема рандомизации сообщений и порядок добавления новых описаны в `NOTES.md`.

## Аватарки

- **Сайт → Telegram.** При запуске бота ссылка на аватарку скачивается на сервере, приводится к квадратному JPEG и отправляется методом `setMyProfilePhoto`. При обычном перезапуске бота та же ссылка повторно не отправляется, но сохранение формы бота со ссылкой всегда ставит аватарку заново (даже если фото потом меняли в самом Telegram). После загрузки панель сразу показывает отправленное фото, а не кэш Telegram. Если загрузка не удалась, в панели появится предупреждение с причиной.
- **Telegram → сайт.** Панель показывает актуальное фото бота из Telegram (кэш в памяти на 5 минут). Токен в браузер не попадает: картинку отдаёт сервер. Пока новая ссылка с сайта ещё не ушла в Telegram, показывается она.
- Для конвертации картинок нужен Pillow (есть в `requirements.txt`).

## Картинка в сообщениях

В настройках бота есть поле «Ссылка на картинку в сообщениях» (в идеале 1680 × 940). Картинка идёт над текстом во всех сообщениях бота, кроме капчи, одним сообщением (фото с подписью); Telegram сам скачивает её по ссылке, после первой отправки используется file_id. Если картинка не отправилась (ссылка недоступна, не изображение, подпись длиннее 1024 символов) — пользователь получает обычный текст.

## Уведомления

Колокольчик вверху. Если уведомления реально включены (браузер разрешил показ и подписка есть), нажатие предлагает отправить тестовое уведомление, оно придёт через 10 секунд; там же можно отключить уведомления. Если разрешение сняли в настройках браузера, сайт считает уведомления выключенными.
