# Bot Rotator

Telegram-бот на aiogram 3 + FastAPI с админ-панелью и автоматической ротацией токенов.
Токены и профили хранятся в PostgreSQL (Neon). Деплой — Render (один Web Service).

## Структура

```
main.py              # FastAPI + запуск супервизора бота (lifespan)
app/
  config.py          # переменные окружения
  db.py              # движок SQLAlchemy/asyncpg, адаптация URL Neon
  models.py          # таблица bot_profiles
  repo.py            # операции с БД
  manager.py         # запуск бота, мониторинг, горячая ротация токенов
  handlers.py        # логика бота (пока /start → «Привет, это тестовый код.»)
  auth.py            # вход по паролю (cookie)
  events.py          # шина событий для SSE и баннеров
  stats.py           # счётчик пользователей в памяти
  push.py            # Web Push
  web.py             # страницы и API панели
  templates/login.html
  static/app.html    # интерфейс панели
  static/sw.js       # service worker для push
render.yaml          # blueprint для Render
```

## Деплой

1. **Neon**: создайте проект, скопируйте Connection string (`postgresql://...?sslmode=require`).
2. **GitHub**: залейте содержимое папки в репозиторий.
3. **Render**: New → Blueprint (подхватит `render.yaml`) или New → Web Service вручную:
   - Build: `pip install -r requirements.txt`
   - Start: `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1`
   - Health check path: `/healthz`
4. Переменные окружения (Render → Environment): `DATABASE_URL`, `ADMIN_PASSWORD` (обязательно), `ADMIN_CHAT_ID`, `VAPID_SUBJECT` (по желанию).
   Вместо переменной можно создать Secret File с тем же именем (`DATABASE_URL`) — он читается из `/etc/secrets/DATABASE_URL`.
   Если переменной нет, сервис всё равно поднимется и откроет порт, а страница панели покажет, чего не хватает.
5. Откройте URL сервиса, введите `ADMIN_PASSWORD` на странице входа и добавьте первый токен. Бот запустится сразу.
   Таблицы создаются автоматически при старте.

Локально: `pip install -r requirements.txt`, задайте переменные из `.env.example`, затем `python main.py`.

## Как работает ротация

- Активен всегда один токен (в БД это гарантирует уникальный индекс). Очередь — по возрастанию `id` среди статуса `queued`.
- Токен выводится из ротации (`blocked`, причина пишется в `last_error`), если:
  - Telegram отвечает 401/404 (токен недействителен, отозван, бот удалён);
  - флуд-контроль просит ждать дольше `FLOOD_ROTATE_THRESHOLD` секунд (по умолчанию 300);
  - подряд `NETWORK_FAIL_THRESHOLD` сетевых ошибок (по умолчанию 8);
  - polling упал `MAX_POLLING_CRASHES` раз подряд (по умолчанию 3).
- Дальше супервизор в том же процессе берёт следующий `queued` токен, поднимает нового бота, обновляет имя/описание и
  запускает polling. Перезапуск приложения на Render не нужен.
- Если очередь пуста — приложение продолжает жить, а панель показывает предупреждение; бот стартует, как только вы добавите токен.
- Из панели можно вручную сделать любой бот активным, вернуть заблокированный в очередь, изменить профиль или удалить бот.

## Профиль

При старте и при каждой смене токена вызываются `getMyName`/`setMyName` и `getMyDescription`/`setMyDescription`
(только если значение отличается и не пустое). У Telegram есть лимит на частоту смены имени — при `retry_after`
бот просто пропустит обновление и повторит при следующем старте.

## Важно знать

- **Аватарка** сохраняется в БД и показывается в панели, но в Telegram не загружается: в aiogram нет готового
  метода для этого. Установить фото можно через @BotFather. Если в актуальном Bot API такой метод появился —
  добавить вызов нужно в `BotManager._apply_profile`.
- **Free-план Render усыпляет сервис** после ~15 минут без входящих запросов, и бот перестаёт опрашивать Telegram.
  Либо платный план, либо внешний пинг `/healthz` каждые 5–10 минут (например, UptimeRobot).
- **Один экземпляр.** Не включайте несколько инстансов/воркеров: два процесса с одним токеном дадут конфликт `getUpdates`.
  При деплое Render ненадолго запускает старую и новую версию параллельно — короткие ошибки 409 в логах нормальны.
- **Токены лежат в БД открытым текстом** (боту они нужны в исходном виде). Панель защищена Basic-авторизацией и
  показывает токены только в маскированном виде; открывайте её только по HTTPS (Render это делает сам).
- Миграции не используются: таблица создаётся через `create_all`. При изменении схемы подключите Alembic.

## Панель

- **Вход** — один пароль (`ADMIN_PASSWORD`), форма на самой странице; после 5 неверных попыток IP блокируется на минуту. Смена пароля разлогинивает всех.
- **Вкладка «Бот»** — текущий основной бот, токен (маскированный, можно показать), число пользователей в реальном времени и время работы в роли основного.
- **Вкладка «Токены»** — очередь: зелёная обводка и «1» у основного, синие 2, 3… у запасных. «Редактировать» включает режим с перетаскиванием (три полоски) и корзиной с подтверждением; тап по карточке в этом режиме открывает правку профиля.
- **Счётчик пользователей** — Bot API не отдаёт список пользователей, поэтому считаются те, кто писал боту или запускал/блокировал его с момента запуска этой версии. Число хранится в памяти, в БД сбрасывается пачкой раз в 15 с, в браузеры уходит через SSE.
- **Сбои и баны** — жёлтый баннер сверху у всех открытых панелей + Web Push. Если токен недействителен: при наличии запасного — переключение на него, токен помечается заблокированным; запасных нет — токен удаляется. Временные сбои (сеть, флуд) при наличии запасного тоже ведут к замене, а без запасного токен остаётся и попытки продолжаются.
- **Push** — кнопка с колокольчиком вверху; работает после разрешения уведомлений в браузере. Ключи VAPID создаются автоматически и хранятся в БД. На iPhone push работает только если сайт добавлен на экран «Домой».
